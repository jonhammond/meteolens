# pbir CLI — project learnings

- A slicer's "default selection" must NOT be a visual-level filter: a Categorical filter in `filterConfig.filters` on the slicer restricts the slicer's own item list (a Units[unit]='Metric' filter made the toggle render only one "Metric" tile, regardless of size/responsive settings). Desktop persists slicer selections under `objects.general.properties.filter` instead (see `pbir-format` skill `examples/visuals/formatted/slicer-flash.json`), which `pbir` (v0.9.29) cannot set. Fix: `pbir rm ".../slicer.Visual/filter:<name>" -f` and rely on the measures' `SELECTEDVALUE(..., "Metric")` fallback for the default.
- `pbir download "<local>.Report" -o <dir>` fetches the linked published copy alongside — diffing it against the local `definition/` is the reliable way to check whether local changes are actually live (they were byte-identical here while the bug persisted, ruling out a stale publish).

- Bare `pbir ls` fails here with `'meteolens.Report' not found`: the `.pbir/active` context file points at a stale name. Always pass the explicit report path (`e89d7c20-65af-95c3-4838-2b659bafdddf.Report`, run from `powerbi/`).
- `pbir model -q` (live DAX execution) cannot work against this report: the dataset lives in the personal "My workspace", and the command resolves workspaces through Fabric Group APIs, which return 401 `GroupNotAccessible` for personal workspaces. `pbir model -d` (schema fetch) uses a different path and works fine.
  - Workaround for DAX probes: POST the query to `https://api.powerbi.com/v1.0/myorg/datasets/<datasetId>/executeQueries` with an `az account get-access-token --resource https://analysis.windows.net/powerbi/api` bearer token. Query must start with `EVALUATE`. Read-only probes only — report mutations still go through `pbir`.
- Push datasets reject `relationships` in the REST create-dataset body (HTTP 400): disconnected tables only. Map coordinates therefore come from SWITCH extension measures over `RealTimeData[location]`, not a related Cities table.
- macOS: `pbir desktop` bridge is unavailable by design; verification is `pbir validate --all` + publish (with consent) + browser check.
- CLI bug (v0.9.29): every filter-enumeration command (`filters list`, `rm .../filter:X`, `filters set/rename`) crashes with "Invalid field reference" on any visual holding a Desktop-authored Advanced filter whose Aggregation-wrapped field lacks a `displayName` — the crash happens during enumeration, so such filters cannot be removed at all. Workaround: rebuild the visual via `pbir cp` from a clean sibling and rebind (stale filters simply aren't carried from a clean source; note `cp` DOES copy the source's filters, so the source must be clean).
- `pbir validate --all` falsely reports measures bound only through `<prop>.cf` (measure-driven titles, background color CF) as UNUSED_EXTENSION_MEASURE — its usage scanner doesn't look inside CF bindings. Verify with `pbir get "<visual>.<prop>.cf"` before believing it.
- altText is a top-level visualContainer field in PBIR that `pbir` (v0.9.29) cannot address via `set` dot-paths or any dedicated command — accessibility alt text currently can't be set through the CLI.
- Extension measures must NOT reference other extension measures on this report (thin report on a push dataset): the service's visual queries omit the referenced measure's DEFINE, so every dependent measure fails at render with "The value for '<measure>' cannot be determined. Either the column doesn't exist, or there is no current row for this column" — even though the same DAX works via `executeQueries` with both DEFINEs present, and `pbir validate` passes. Inline the shared expression (e.g. `SELECTEDVALUE('Units'[unit], "Metric")`) into each dependent measure instead of factoring it out.
- Slicer `data.mode = 'HorizontalList'` (valid in the pbir catalog) is ignored by the service renderer — the slicer falls back to a vertical radio list and extra items get clipped by the visual height. Use the Desktop-native combo instead: `data.mode = 'Basic'` + `general.orientation = 1` for a horizontal tile slicer.
- A horizontal tile slicer also needs `general.responsive = false`. Left at its default (true), the slicer collapses under a small container and renders only the first tile — a two-value Metric/Imperial toggle at 200x48 showed just one "Metric" tile with no second option to click, which looks exactly like "the toggle does nothing". Give it real room too (280x56 works for two tiles). Reference shape: `pbir-format` skill, `examples/visuals/formatted/slicer-flash.json`.
- `pbir` writes every numeric literal in Double form (`1D`, `12D`) even for enum-typed properties like `general.orientation`. That is what Desktop produces as well, so `"Value": "1D"` is correct and not the cause of a mis-rendering enum — don't chase it.
- Narrow cards (184px) overflow their box when the title is a long measure-driven string ("Avg. Cloud Cover (%)"). Cards do not wrap titles by default: set `title.titleWrap = true` plus a smaller `title.fontSize` (11 fits two lines at 184px).
