Learnings from Claude about connecting to semantic models via the connect-pbid skill

- Report-level **extension measures render blank in Desktop against this push dataset** while rendering correctly in the service. Verified 2026-08-19 by elimination: VM copy's `reportExtensions.json` is byte-identical to the repo (same SHA-256/size/mtime), `definition.pbir` connection strings match exactly (dataset 2d64d5e3), the measure DAX evaluates fine via `executeQueries` (cloud 12.75, AQI 30.7, 4308 rows), `'Units'[unit]` resolves with both values, Desktop holds a live HTTPS session, and the local AS workspace is an empty scratch engine with no user DB (normal for live-connect). Conclusion: Desktop-side limitation injecting session-scoped report measures against a REST push dataset (no XMLA endpoint) — not a sync, data, or auth fault. Do not chase it as a report bug; the service (ExportTo API) remains the authoritative render check.
- VM diagnostics that work read-only over `prlctl exec`: `Get-Process PBIDesktop/msmdsrv`, `Get-FileHash` for repo-vs-VM comparison, `Get-NetTCPConnection -OwningProcess <pid>` to prove service connectivity, and `AnalysisServicesWorkspaces\*\Data\msmdsrv.log` for engine startup. `Traces\Performance\*.log` files are 0 bytes unless Performance Analyzer is recording — not a source of error detail.

- `prlctl exec` runs outside the interactive Windows session: PBIDesktop shows `MainWindowHandle 0`, so `CloseMainWindow()`/window-title methods fail; ask the user to close/restart Desktop instead.
- zsh `echo -n` mangles `\U`/`\u` in PowerShell strings before Base64-encoding; use `printf '%s'` when building `-EncodedCommand` payloads.
- A hand-authored `.pbip` needs `$schema` matching `^https://developer.microsoft.com/json-schemas/fabric/pbip/pbipProperties/1.x.x/schema.json$` — `fabric/item/pbip/...` is rejected (UnrecognizedSchemaVersion). Pre-restart Desktop instances without the PBIP preview feature active fail *silently* on .pbip open; the toggles only apply at launch.
- Desktop rejects PBIP/PBIR files with a UTF-8 BOM; Windows PowerShell 5.1 `Set-Content -Encoding UTF8` writes a BOM — use `[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))` instead.
- VM "Windows 11": Shared Profile maps only Desktop/Documents/Downloads unless Host defined sharing is enabled; VM's C:\Users\...\Documents is local to the VM, not the Mac's ~/Documents.
